2026-05-28 작성 · 다음 회의 준비 자료 · 대상: 비전문가 학습조직 · 0주차 피드백 반영판

★ 이 자료가 답하려는 것

지난 0주차 자료(7개 모델 비교)를 보고 "용어도 작동 원리도 모르겠고 질문만 많아진다"는 피드백이 있었습니다. 그래서 이번엔 "고르는 것"보다 "이해하는 것"을 먼저 둡니다. 순서대로 읽으면 다음 5개 질문에 답할 수 있도록 구성했습니다.

  1. VLA 에 무엇이 입력되어 어떻게 로봇 행동으로 출력되는가?
  2. VLA 모델은 어떤 부품(구성단위)으로 되어 있는가?
  3. 우리가 데이터를 추가 학습(fine-tune)하면 그 부품 중 어디가 바뀌는가?
  4. 대표 4개 모델(OpenVLA · π0 · Gemini Robotics · GR00T)은 무엇이 어떻게 다른가, 그리고 오픈소스인가?
  5. 우리 PC(24GB)에서 무엇을 실제로 실습할 수 있는가?

중간중간 나오는 용어(VRAM, LoRA, diffusion 등)는 3부 용어 사전에서 기능 중심으로 풀어 설명합니다.

1부 · 개념
VLA 란 무엇인가 — 입력에서 행동까지

VLA = Vision-Language-Action (시각–언어–행동). 카메라가 본 장면(Vision)과 사람이 준 말(Language)을 받아서, 로봇이 해야 할 움직임(Action)을 하나의 AI 모델이 직접 만들어냅니다.

비유 — 사람이 "컵을 집어 줘"라는 말을 듣고, 눈으로 컵을 보고, 손을 뻗어 집는 그 과정 전체를, 따로 노는 프로그램 여러 개가 아니라 하나의 뇌가 처리한다고 보면 됩니다.

📷 카메라로봇이 보는 장면
+
💬 명령"컵을 집어 줘"
→
🧠 VLA 모델보고·이해하고·계획
→
🦾 행동관절 각도·그리퍼
기존 로봇과 무엇이 다른가 — 예전에는 "물체 인식 프로그램", "명령 해석 프로그램", "동작 계획 프로그램"이 따로 있어서, 상황이 조금만 바뀌어도 연결이 끊겼습니다. VLA 는 이 셋을 한 모델 안에 합쳐, 사전학습으로 얻은 "세상에 대한 일반 지식"을 활용해 처음 보는 물건·명령에도 더 유연하게 대응합니다.

2부 · 구조
VLA 모델의 구성단위 — 3개의 부품

거의 모든 VLA 는 아래 3개의 부품(블록)이 이어진 형태입니다. 이 구조를 알면 "fine-tune 할 때 어디가 바뀌는가"(4부)가 자연스럽게 이해됩니다.

입력이미지 + 명령
(+ 관절 상태)
→
① 비전 인코더이미지 → 특징
→
② 언어모델 백본보고+듣고 → 의도
→
③ 액션 헤드의도 → 모터 신호
→
출력행동(action)
부품하는 일비유대표 기술
① 비전 인코더
(Vision Encoder)		 카메라 픽셀을 AI가 다룰 수 있는 "특징(feature)" 으로 변환. "어디에 무엇이 있다"를 정리 눈 → 시각 피질 SigLIP, DINOv2, ViT
② 언어모델 백본
(VLM / LLM Backbone)		 명령의 뜻을 이해하고, 시각 정보와 합쳐 "무엇을 어떤 순서로 할지" 의도를 만든다. VLA 의 몸집 대부분을 차지 전두엽(생각·판단) Llama, PaliGemma, Qwen-VL
③ 액션 헤드
(Action Head / Expert)		 고수준 의도를 실제 모터가 실행할 "관절 각도·그리퍼" 같은 저수준 숫자로 변환 소뇌(움직임 실행) 토큰 예측 / diffusion / flow matching

핵심 — ②번 언어모델 백본이 보통 가장 크고(수 B 파라미터), 인터넷 규모로 사전학습되어 "일반 지식"을 담고 있습니다. ③번 액션 헤드는 상대적으로 작고, "이 로봇의 몸"에 특화된 부분입니다.

3부 · 용어
꼭 알아야 할 용어 — 기능 중심으로

회의에서 나왔던 질문(VRAM·LoRA·RL vs VLA 등)을 "그래서 이게 뭐고 왜 중요한가" 중심으로 정리했습니다.

VRAM (GPU 메모리)
그래픽카드 안의 작업 공간. 모델의 숫자(가중치)와 계산 중간값이 전부 여기 올라가야 함.
왜 중요 — 모델이 크거나 한 번에 많이 처리하면 VRAM이 모자라 학습이 멈춤. 우리 PC는 24GB.
사전학습 vs 미세조정
사전학습(pretraining)= 대규모 데이터로 "기본기"를 만든 무거운 과정(대기업이 함). 미세조정(fine-tune)= 그 모델을 우리 로봇·작업에 맞게 살짝 조정(우리가 함).
왜 중요 — 우리는 처음부터 학습할 필요 없이, 공개된 사전학습 모델을 받아 fine-tune만 하면 됨.
LoRA
모델 전체를 다시 학습하지 않고, 각 부품에 "작은 보조 모듈"만 붙여 그것만 학습하는 기법.
왜 중요 — VRAM을 크게 아껴서, 24GB 같은 소비자 GPU에서도 fine-tune 가능. 성능은 전체 학습과 거의 같음.
RL vs VLA(모방학습)
RL(강화학습)= 로봇이 직접 시행착오하며 보상으로 배움(느리고 위험). VLA= 사람 시연을 보고 따라하는 모방학습이 기본(빠르고 안전).
왜 중요 — 우리의 텔레옵 시연 데이터가 곧 VLA 학습 재료. RL은 나중에 미세 최적화에 보조로.
Action 표현 ①: 이산 토큰
연속적인 관절 값을 칸으로 나눠(예: 0~10도=토큰0), 언어모델이 "다음 토큰" 맞히듯 행동을 예측.
빠르고 단순(OpenVLA). 단, 미세한 움직임은 다소 거칠 수 있음.
Action 표현 ②: Diffusion
무작위 노이즈에서 시작해 여러 단계로 다듬어 매끄러운 행동을 만들어냄.
정밀하고 부드러움(GR00T 액션 헤드). 단계가 많아 상대적으로 느림.
Action 표현 ③: Flow matching
Diffusion과 비슷하지만 1~3단계로 확 줄여, 정밀함과 속도를 동시에.
최근 주목(π0). 50Hz 실시간 제어 가능.
EEF · 텔레옵 · 시연
EEF= 로봇 팔 끝의 손/그리퍼(위치 XYZ+회전). 텔레옵= 사람이 VR·장갑으로 로봇을 원격 조종. 시연(demo)= 그렇게 모은 "올바른 행동" 기록.
우리의 Manus 장갑·Quest3가 바로 텔레옵 → 시연 데이터 수집 장치.
Embodiment (로봇 몸의 종류)
로봇마다 팔 길이·관절 수·그리퍼가 다름. 여러 로봇 데이터를 한 모델로 학습하면 일반화가 좋아짐.
Open X-Embodiment = 22개 로봇 데이터 모음. 한 모델이 여러 몸에 적응.
Action chunk · 제어 주파수
한 번 추론에 미래 여러 스텝(chunk)을 한꺼번에 출력. 제어 주파수= 초당 몇 번 새 명령을 내는가(예: 50Hz).
chunk가 길면 부드럽고 효율적. 주파수가 높을수록 반응이 민첩.

4부 · 미세조정
Fine-tune 하면 어디가 바뀌나 + 우리 24GB

2부의 3개 부품 중 어디의 가중치를 바꾸느냐가 곧 fine-tune 방식의 차이이고, 그게 VRAM 부담을 결정합니다.

방식바뀌는 부품VRAM 부담성능우리 24GB
Full fine-tune ① + ② + ③ 모든 가중치 매우 큼 최고 ✗ 대부분 불가
LoRA 각 부품에 붙인 작은 보조 모듈만
(원본은 얼려둠)		 중간 (원본의 1/3) full과 거의 동일 ✓ 대체로 가능
Action-head-only ③ 액션 헤드만

우리에게 주는 결론 — 24GB 에서는 처음부터 학습(full pretraining)은 불가능하지만, 공개된 사전학습 모델에 LoRA 또는 액션 헤드만 fine-tune 하는 방식이면 충분히 실습 가능합니다. 그래서 "오픈소스로 가중치가 공개됐는가"가 모델 선택의 핵심 기준이 됩니다.

5부 · 모델
대표 4개 모델 집중 분석

각 모델을 구성단위 / 입력·출력 / fine-tune 단위 / 오픈소스 여부 / 24GB 실습 관점에서 봅니다. 공개 여부 태그: 오픈 코드+가중치 공개 · 부분 일부 제약 · API 비공개·클라우드 전용.

6부 · 로봇
왜 Franka 로 시작하는가

회의에서 나온 "Franka 예제가 많은가?"에 대한 답 — 매우 많습니다. 사실상 표준입니다.

  • DROID 데이터셋 = 100% Franka Panda (18개 팔, 76,000 궤적, 350시간). 13개 기관 공동 수집.
  • Open X-Embodiment = 전체의 85%가 단 4개 로봇(Franka 포함). Franka는 그중 단일 최대.
  • OpenVLA·π0 모두 Franka/DROID 사전학습 체크포인트 제공. GR00T는 Isaac Lab 에서 Franka pick&place 예제.
  • 비전문가 진입용: Panda-Gym, Franka-Kitchen 등 쉬운 시뮬 환경 다수.
→ Franka 는 "데이터·예제가 가장 많아 막힐 일이 적은" 출발점. 우리 Isaac Lab 에도 Franka 환경이 기본 포함되어 있어 시뮬 실습에 적합.

7부 · 확장
VTLA — 촉각을 더한 VLA (우리 Manus 장갑과 연결)

VTLA = Vision-Tactile-Language-Action — 시각·언어·행동에 촉각(Tactile)을 더한 확장형. 조립·삽입·집기처럼 손이 가려지고(occlusion) 힘 조절이 중요한 "접촉이 많은 작업"에서 시각만 쓰는 VLA보다 크게 우수합니다.

  • 연구 사례: VTLA(2025-05, 삽입 작업 90%+ 성공), OmniVTLA(2025-08).
  • 우리와 직결: MANUS 장갑 + OSMO 촉각 센서 결합 실험에서 성공률 56%(시각만) → 72%로 향상된 사례가 보고됨.
→ 우리는 이미 Manus 장갑으로 손 자세·손가락 데이터를 모읍니다. 여기에 힘/촉각 정보를 더하면 VLA를 VTLA로 확장할 수 있는 자연스러운 길이 있습니다. (1주차 범위는 아니고, 중기 확장 방향으로 기억해 둘 포인트.)

8부 · 실습
우리 PC(24GB)에서 할 수 있는 기초 실습

"읽기"만으로는 추상적이라, 손으로 한 번 돌려보는 게 이해에 가장 빠릅니다. 24GB 에서 현실적인 후보를 비교했습니다.

추천 1주차 실습 — 2단계

AOpenVLA로 "VLA가 행동을 출력하는 것" 확인 (눈으로 숫자 확인, 가장 안전)

  1. 가상환경 + 의존성 설치 (HuggingFace Transformers 기반)
  2. openvla/openvla-7b 가중치 자동 다운로드 (약 14GB, 24GB에 적재)
  3. 샘플 이미지 + "Pick up the cube" 명령 입력 → 7-DoF action 값이 출력되는지 확인
  4. 명령을 바꿔가며 출력이 달라지는지 관찰 → "입력→행동" 직관 체득

BIsaac Lab + GR00T로 "로봇이 움직이는 것" 보기 (우리 인프라 활용, 시각적)

  1. ~/IsaacLab + NVIDIA/Isaac-GR00T 준비
  2. GR00T 사전학습 모델 다운로드 → DROID 샘플로 inference (action 예측)
  3. Isaac Lab의 Franka pick&place 환경에 예측 action 입력
  4. 시뮬레이션 화면에서 Franka 팔이 명령대로 집고 놓는 영상 확인
실습 목표 — (A)로 "VLA는 정말 입력을 받아 행동 숫자를 뱉는다"를, (B)로 "그 숫자가 실제(시뮬) 로봇을 움직인다"를 눈으로 확인. 이 두 가지를 경험하면 "VLA가 막연하지 않고 손에 잡힌다"는 감각이 생깁니다. fine-tune(우리 데이터 추가 학습)은 그 다음 주차로.

제안 — 회의 전에 제가 A안(OpenVLA inference)을 우리 PC에 실제로 설치·실행해 두고, 캡처/로그를 함께 준비할 수 있습니다. 그러면 회의에서 "이미 돌아가는 것"을 보여줄 수 있습니다.
